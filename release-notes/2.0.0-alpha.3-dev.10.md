# 2.0.0 Alpha 3 Dev 10

## Purpose

Dev.10 completes the Action responsiveness work reported by Harish / Codecity001. It keeps the Dev.9 cached-status and compatibility optimizations, then prevents the already-cached status block from being rendered again whenever the user returns from Settings, Debug, or Advanced without changing state.

## Action UI render fix

- The main Action loop tracks whether the status block has already been shown.
- Status is rendered on initial load and again only after a state-changing operation marks it dirty.
- Returning from a read-only submenu goes directly back to the Action choices without printing the complete status block again.
- Full compatibility refreshes remain limited to initial load, explicit Debug → Status, and state-changing transactions.
- The existing dashboard performance receipt remains available for refresh, cached-print, and main-menu render counts.

## Dev.9 performance work retained

- No recursive `/data/adb`, `/debug_ramdisk`, or `/sbin` meta-backend search.
- `supported_versions.json` is structurally validated once per helper process.
- Device, Android, and exact-build evidence are derived through one combined probe.
- The obsolete Action call to the old toggle collector remains removed.
- Duplicate update-channel fallback logic remains consolidated.
- Debug ZIP collection, transactional Thermal changes, local Fix 5 validation, Bootguard, and pTune safeguards remain unchanged.

## Evidence

Harish supplied an Action log showing approximately 670 ms startup on his test build and immediate return from Advanced to the Action choices without a repeated status block. The Dev.9 Mustang Stable runtime proof already demonstrated one full status refresh across two main-menu renders; Dev.10 adds the missing render-suppression guard and CI contract for the follow-up behavior.

## Safety and publication boundary

This is a private test-line identity. It does not create a tag, release, public asset, or update-channel change. A fresh exact-package install, reboot, and Action run remain required before any publication decision. Roll back on-device by reinstalling the public Dev.8 package or the verified Dev.9 test package.
