# 2.0.0 Alpha 3 Dev 13

Private vNext test line. Not published.

## Root causes from Dev.12 live verification

- Pixel 10 Pro XL `mustang` exposes the Emerald Hill devfreq node as `/sys/class/devfreq/eh_freq`. Dev.12 required Emerald/lz77/legacy EH naming and therefore rejected the real node before any write.
- Selected ZRAM properties were applied before Android completed boot. The platform could rewrite the LMK property later, leaving `ro.lmk.swap_free_low_percentage` unset in the post-reboot check.
- OTA rematerialization rewrote `install-state.txt` without the effective polling, outdoor and ZRAM-materialization fields. Runtime remained healthy, but diagnostics lost those selections.
- `dynamic_local_validated` and `PLATFORM_SUPPORTED` are the current dynamic-validation contracts. Legacy `dynamic_stock_validated_exact_verified` and `EXACT_BUILD_SUPPORTED` expectations are not restored.

## Dev.13 changes

- Admits the exact `eh_freq` and `eh-freq` Pixel node names while continuing to reject unrelated `*_freq` devfreq nodes.
- Keeps the kernel maximum as the upper bound and preserves the existing write/readback verification and baseline restore.
- Reapplies the runtime-only ZRAM property set once after Bootguard `success-verify`.
- The verified-boot property mode never restarts `mmd` and defers Emerald Hill activation to the existing guarded service block.
- Logs LMK readback as active or nonfatal-unavailable instead of making a property-observability problem boot-critical.
- Persists `thermal_polling_effective`, `thermal_outdoor_profile`, `zram_fstab_materialized`, `zram_enabled` and the dynamic profile-state contract after OTA rematerialization.

## Safety boundaries

- No unbounded watcher or periodic devfreq writer is added.
- Emerald Hill remains optional, explicit and fail-open to adaptive lz77eh ZRAM.
- No frequency above the kernel-exposed maximum is requested.
- Thermal overlay failure handling and Bootguard-v3 remain authoritative.
- No stable/prerelease channel, tag or public release is changed by this integration.

## Validation

- Adds a fixture using the real `eh_freq` basename without a synthetic `name` file.
- Adds a `gpu_freq` decoy and verifies it is not modified.
- Verifies post-Bootguard property ordering, no `mmd` restart in verified-boot mode and no duplicate EH apply.
- Verifies complete post-OTA runtime-selection state and absence of stale exact-build terminology.
- Dev.12 regression coverage remains enabled.

## Rollback

- Select standard ZRAM/no Emerald Hill lock and reboot.
- Disable ZRAM and reboot to remove the 100% ZRAM layout.
- Disable/remove the module and reboot for full module rollback.
