# 2.0.0 Alpha 3 Dev 17

Public Alpha prerelease with the cumulative changes made after `2.0.0-alpha.3-dev.10`.

## OTA and Bootguard hardening

- Tracks device, Android version, build ID, incremental, and fingerprint as the active platform tuple.
- Quarantines only this module's three controlled Thermal overlays during a platform transition.
- Recaptures stock sources and republishes overlays only after local transactional validation.
- Keeps unsupported platforms or failed materialization stock-only.
- Separates prior-attempt evaluation, final-state arming, and verified runtime success.
- Requires completed boot, safe compatibility output, exact active-overlay agreement, and Thermal runtime evidence before clearing the pending state.

## ZRAM 100 percent and Emerald Hill

- Adds 100-percent ZRAM sizing with `lz77eh` and `vm.swappiness=100`.
- Makes ZRAM 100 percent a Fresh-install default.
- Keeps Emerald Hill adaptive for normal daily operation.
- Provides a separate explicit maximum-frequency minimum lock with a clear power and heat warning.
- Deduplicates physical `eh_freq` sysfs aliases and stores one baseline per physical device.
- Restores old duplicate baselines from the first real original minimum.
- Leaves Android's stock LMK swap-low policy untouched.
- Uses one-shot post-Bootguard application with no permanent watcher.

## Installer, Action, and observability

- Makes Polling Mod, ZRAM 100 percent, and Verbose Logging the Fresh defaults.
- Keeps Stock Thermal as the Fresh profile default while allowing Safe, Plus, and Outdoor Extended as explicit choices.
- Verifies every installer and Action route, including Back and timeout behavior.
- Uses one transactional ZRAM layout materializer across installation, Action, and standalone helpers.
- Preserves unrelated configuration when pTune override is disabled.
- Separates pTune, ZRAM, and Emerald Hill risk receipts.
- Handles an already-correct packaged ZRAM fstab idempotently in Magisk staging.
- Preserves exact materializer failure evidence in `guard/install-zram-layout.log`.
- Fixes packaged-debug copy helpers so destination paths cannot compound.
- Preserves complete installation evidence while merging current runtime state after boot.
- Treats explicitly selected Thermal profiles as valid instead of requiring Stock after installation.
- Keeps the Magisk manager description live by replacing only `description=` with current Polling, Thermal, and ZRAM status; module identity, version, versionCode, author, and update URL remain unchanged.

## Regression coverage

- Adds platform-transition and Bootguard-v3 regression tests.
- Adds fake-devfreq alias, decoy-node, maximum-lock, and legacy-baseline restore fixtures.
- Adds full installer/Action route and helper-side-effect matrices.
- Simulates Magisk staging that refuses replacement of an existing destination.
- Adds boot-time install-state preservation and unchanged-second-boot idempotence tests.
- Keeps the older dev.12, dev.14, dev.15, dev.16, and lean-package contracts running in CI.

## Verified Mustang runtime

The exact public package was freshly installed and verified after reboot on Pixel 10 Pro XL / Mustang with Android 17 build `CP2A.260705.006 / 15641320`.

Verified effective configuration:

- Polling Mod with all 22 controlled values active at `5000` and no remaining controlled `300000` values;
- manually selected Outdoor Extended with all three active Thermal overlays matching the validated module files;
- ZRAM active near 100 percent of RAM using `lz77eh`;
- `vm.swappiness=100` and memory-management daemon running;
- Emerald Hill adaptive at 200–1066 MHz with one physical node and deduplicated aliases;
- pTune override off;
- stock LMK policy with no module-forced swap-low override;
- complete install-state schema retained after boot, including validation hashes and separate runtime profile state;
- Bootguard, post-boot ZRAM reapply, adaptive Emerald Hill, Thermal logcat, and tombstone checks passed.

The final device verification produced 150 functional PASS results. Its only warning was the non-authoritative generic process-name probe; current Thermal logcat evidence was present. The package-hash checker initially flagged `module.prop` because the module intentionally writes its live manager status into `description=` after boot. A rooted byte diff confirmed that this was the sole change and matched the repository's `status_update_description()` contract.

## Installation defaults

Fresh installation starts with:

- Polling Mod;
- Stock Thermal;
- ZRAM 100 percent;
- adaptive Emerald Hill;
- pTune override off;
- Verbose Logging.

Existing users may choose **Use last** to preserve saved selections. Outdoor Extended remains an explicit manual choice.

## Supported-platform policy

Supported Pixel 10 devices on Android 17 may request the full profile range. Exact build IDs are evidence, not the activation gate. Local stock-derived materialization and independent validation remain fail-closed authorities. Unsupported devices, unsupported Android versions, unreadable stock sources, or failed validation keep Thermal overlays disabled.

## Publication and rollback

This build is published as an Alpha prerelease. The stable channel remains unchanged. Roll back on-device by reinstalling the previous verified prerelease or by disabling/removing the module and rebooting.
