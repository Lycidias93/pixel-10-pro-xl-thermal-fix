# 2.0.0 Alpha 3 Dev 9

## Purpose

Dev.9 implements the Action responsiveness review supplied by Harish / Codecity001 while retaining the Dev.8 Fix 5 Thermal policy and fail-closed validation model.

## Action performance

- The Action dashboard performs a full status/compatibility refresh only when its cached snapshot is dirty or when the user explicitly requests Debug → Status.
- Returning from Settings, Debug, or Advanced now renders the cached status instead of repeating the complete compatibility scan on every menu loop.
- Thermal and ZRAM changes still perform one fresh verification after the transaction before the new status is shown.
- pTune changes invalidate the cache and are verified once on the next dashboard render.
- Action writes a small performance receipt with refresh, cached-print, and main-menu render counters.

## Compatibility and admission performance

- Meta-backend discovery now scans only installed and staged module metadata instead of recursively traversing `/data/adb`, `/debug_ramdisk`, and `/sbin` to depth five.
- Supported-version manifest structure is validated once per helper process.
- Device, Android, and exact-build evidence are derived by one cached manifest probe instead of multiple complete validation passes.

## Cleanup

- The Action Debug menu toggles logging state directly rather than invoking the old read-only toggle collector.
- Duplicate missing-update-switch branches were consolidated.
- The packaged debug ZIP collector remains available and unchanged under Debug → Collect ZIP.

## Safety retained

- Dev.8 supported-platform admission remains unchanged: supported Pixel 10 devices on Android 17 may request all Outdoor profiles.
- Local stock-derived Fix 5 materialization and independent validation remain the final fail-closed authority.
- Transactional Action changes, Bootguard, pTune policy, and rollback behavior remain enabled.

## Evidence boundary

CI must verify shell syntax, the Action transaction contract, shallow backend probing, cached supported-manifest validation, package exclusions, and the deterministic Dev.9 ZIP. A fresh install/postboot run and real Action timing test are still required before any Dev.9 publication decision.
