# Pixel 10 Thermal & Memory Control 2.0.2

2.0.2 is a focused Stable Dynamic V2 hotfix for the real August multiline `HotThreshold` layout.

## Fixed

- Completes multiline-aware `HotThreshold` handling in the **materializer**, not only the independent validator.
- Makes the allowed-diff normalizer understand the same multiline threshold arrays.
- Fixes the fail-closed `rc=63` installation rejection reproduced on Pixel 10 Pro XL (`mustang`) with Android 17 August Stable `CP2A.260805.005` when an Outdoor profile is selected.
- Keeps exact per-value Outdoor delta checks, target-zone matching, sentinel preservation, controlled-file scope and fail-closed rollback unchanged.

## Root cause

2.0.1 correctly taught the independent Outdoor-delta validator to parse compact and multiline arrays, but the Stable Dynamic V2 materializer still changed only compact single-line `HotThreshold` arrays. On the newer August throttling file, Polling was materialized but the multiline Outdoor thresholds were left at stock values. The independent validator then correctly rejected the mismatch with `rc=63`.

This is not a KernelSU migration problem and is not specific to upgrading from 1.5.1. The preserved older module/profile merely exposed the affected Outdoor materialization path during the update.

## Regression proof

The fix was reproduced against the attached XDA failure evidence for `mustang / CP2A.260805.005` and the Stable path now validates the August shape with:

- 3 controlled Thermal files
- 12 target zones / 12 threshold arrays
- 84 controlled threshold values
- exact `+3 C` validation for Outdoor Extended
- all controlled Polling replacements preserved

Repository CI additionally covers Stock, Outdoor Safe, Outdoor Plus and Outdoor Extended using multiline throttling fixtures, plus Dynamic build admission, Outdoor delta rejection behavior and the lean release package contract.

## Upgrade

Install 2.0.2 over the existing module and reboot. There is no need to wipe module state first. If a previous 2.0.1 attempt failed closed, the previously active module was intentionally kept in place and can be upgraded normally.

Pixel 9-series / Pixel 10a expansion remains on the separate 2.1 prerelease line.
