# Pixel 10 Thermal & Memory Control 2.0.3

2.0.3 is a focused Stable runtime-evidence hotfix on top of 2.0.2.

## Fixed

- Fixes the post-reboot `dynamic_materialization_invalid` false negative reported after a successful 2.0.2 install where the active vendor files already matched the validated overlay and all 22 controlled Polling values were active at 5000 ms.
- Makes runtime status and Bootguard verification consume the canonical persistent validation state under `/data/adb/pixel-10-pro-xl-thermal-fix/validation` directly.
- Removes runtime correctness dependence on legacy module-side validation symlink aliases that can be fragile across root-manager staging and mount backends.
- Keeps the 2.0.2 August multiline `HotThreshold` materializer fix, exact Outdoor delta validation, source-cache checks, active vendor hash checks, Polling guards and fail-closed recovery unchanged.

## Evidence

The reporter's 2.0.2 install package exactly matched the published Stable asset and completed successfully on `mustang / CP2A.260805.005` with KernelSU. Install-time validation passed for all three controlled Thermal files, 22/22 Polling replacements and Outdoor Extended at 12 target zones / 84 threshold values. After reboot, the dashboard still reported `dynamic_materialization_invalid` despite `Vendor match: yes`, `Active values: yes`, and 22 active 5000 ms values. This isolates the defect to runtime evidence lookup rather than Thermal materialization itself.

## Upgrade

Install 2.0.3 over the existing module and reboot. No wipe or config reset is required.
