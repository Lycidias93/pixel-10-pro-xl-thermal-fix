# Pixel 10 Thermal & Memory Control 2.0.4

2.0.4 is a focused Stable fresh-cache manifest hotfix on top of 2.0.3.

## Fixed

- Fixes Dynamic Thermal materialization when a supported device/build tuple has no existing stock cache yet.
- Writes the source-cache and patch-manifest TSV headers with real tab delimiters instead of literal `\t` text.
- Prevents the subsequent manifest reader from interpreting the malformed header as a filename and aborting the patch transaction before validation.
- Keeps the 2.0.3 canonical persistent runtime-evidence fix, 2.0.2 August multiline `HotThreshold` materializer support, exact Outdoor delta validation, Polling guards, active vendor verification and fail-closed rollback unchanged.

## Reporter evidence

Thanks to **HARISH / Codecity001** for the Pixel 10 Pro (`blazer`) August Stable package-debug capture that exposed the missing fresh-cache path.

The reported 2.0.2 attempt used Android 17 `CP2A.260805.005` with Magisk 30.7, Polling Mod and Outdoor Safe. It failed before a Thermal overlay or validation state was promoted. The captured fresh source manifest had a literal `file\tsha256\tbytes\tpolling_300000` header while its data rows were correctly tab-delimited, isolating the defect to manifest serialization rather than the Blazer stock Thermal files or Magisk.

A fresh-cache regression is now part of CI so the manifest must be generated from scratch and consumed successfully before release.

## Upgrade

Install 2.0.4 over the existing module and reboot. No wipe or config reset is required.
