# Pixel Thermal & Memory Control 2.1.0-alpha.1

This is the first **vNext device-expansion prerelease**. Stable users should remain on 2.0.1 unless they are intentionally testing the new device-family support.

## Main changes

- Adds experimental Android 17 admission for the **Pixel 9 series**: Pixel 9 (`tokay`), Pixel 9 Pro (`caiman`), Pixel 9 Pro XL (`komodo`), Pixel 9 Pro Fold (`comet`) and Pixel 9a (`tegu`).
- Adds experimental Android 17 admission for **Pixel 10a (`stallion`)**.
- Replaces the hard-coded third Thermal file assumption with a fail-closed layout detector. The controlled set remains exactly three files: `thermal_info_config.json`, `thermal_info_config_charge.json`, plus either `thermal_info_config_throttling.json` or `thermal_info_config_lpm.json` according to the admitted device family and local stock layout.
- Adds layout-aware source caching, atomic overlay materialization, patch manifests, active-runtime verification and independent Outdoor delta validation.
- Adds an optional **Support Snapshot (read-only)** choice to the installer. It collects the embedded v5 support package after installation without enabling or changing Thermal/Polling settings.

## Conservative policy for Pixel 9 / Pixel 10a

The new Tensor G4-family targets are deliberately more restrictive in this first alpha:

- Outdoor is capped at **Stock / Outdoor Safe +1 °C**. +2 °C and +3 °C remain blocked until device runtime evidence exists.
- Full Bootguard verification is forced; the fast unchanged-state path is not trusted for these experimental targets yet.
- Automatic Thermal rematerialization after a firmware/platform transition is disabled. The stale module overlay is removed and the prerelease must be reinstalled before Thermal is re-enabled.
- Any unsupported or ambiguous Thermal layout fails closed; ZRAM remains available independently.

## Pixel 10a evidence

Allen Chang's Pixel 10a / `stallion` support snapshot on Android 17 build `ZP11.260717.006` established a different stock controlled-file family from the Pixel 10 flagships:

- `thermal_info_config.json`
- `thermal_info_config_charge.json`
- `thermal_info_config_lpm.json`

The collected stock files contained 37 `PollingDelay=300000` entries across the three selected files: 23 + 11 + 3. This prerelease uses that evidence to select the `base + charge + lpm` family for `stallion`; it does not claim post-reboot Thermal runtime verification on Pixel 10a yet.

## Pixel 9 status

Pixel 9-series codenames and Android 17 platform admission are included for tester coverage, but **no Pixel 9-series device is marked exact-verified in this alpha**. Local stock layout, source structure and exact-diff validation remain mandatory before an overlay can be produced. Please send the installer Support Snapshot and post-reboot runtime evidence for each device tested.

## Pixel 10 regression baseline

The existing Pixel 10 family keeps the `base + charge + throttling` controlled layout and the current Dynamic V2 safety model.

Additional August Stable regression evidence on Pixel 10 Pro XL / `mustang`, build `CP2A.260805.005`, passed the complete AIO verifier on 2026-08-07 with `preflight_failures=0`, compatibility exit 0, verification failures 0, collector exit 0 and workflow exit 0. The tested module was the `2.0.1-hotfix.1` candidate, so this is a runtime regression baseline rather than byte-identical proof of the public 2.0.1 ZIP.

Existing August Stable / KernelSU post-reboot evidence, August Canary tester evidence and July Stable / Magisk regression coverage remain part of the 2.0.1 baseline.

## Online / installer debug

The embedded v5 collector supports:

- `support`: privacy-reduced hardware, stock Thermal layout, module state and runtime topology evidence without logcat/dmesg contents.
- `runtime`: extended filtered runtime/root logs for an actual failure investigation.
- archive fallback: ZIP, 7z-backed ZIP, then tar.gz.
- private execution/work directories rather than Android shared-storage execution.

The installer option uses **support mode** and remains nonfatal if collection or packaging is unavailable.

## What testers should report

For Pixel 9-series and Pixel 10a testing, please include:

1. device codename and Android build,
2. root implementation,
3. installer result,
4. generated Support Snapshot archive,
5. after reboot: whether the device booted normally and the module P/T/Z/L status,
6. a runtime debug package if Bootguard or Thermal verification does not become green.

Do not enable higher Outdoor profiles by modifying the module files manually; the +1 cap is intentional for this alpha.
