# Pixel Thermal & Memory Control 2.1.0-alpha.10

This is a **public vNext prerelease**. Stable users can remain on 2.0.4; Alpha10 extends the sparse/no-overlay Thermal materialization model to the supported Pixel 9 and Pixel 10 families while keeping the existing Pixel 11 safety policy intact.

## New in 2.1.0-alpha.10

- **Pixel 9/10 now use sparse Thermal materialization.** Only Thermal JSON files with a real admitted policy change are placed in the module overlay.
- **Stock + Stock produces no Thermal JSON overlay.** When generated bytes equal the stock source, the device continues using the vendor Thermal files directly.
- **Changed profiles materialize only changed files.** Outdoor and polling changes no longer force unrelated Thermal JSON files into the overlay.
- **Validation remains fail-closed.** Sparse and zero-overlay states are verified against the cached stock source and generated output hashes, with dedicated regression coverage for Pixel 10.
- **Boot-time sparse state is preserved.** Reboot validation now honors the recorded materialization mode and overlay-file list, preventing unnecessary rematerialization and false pTune override failures.
- **Pixel 11 behavior is unchanged.** Tensor G6 keeps stock-only polling/timing, bounded Outdoor Safe behavior and independent HotHysteresis / MaxReleaseStep recovery controls.

## WebUI and shared core

- **WebUI Core updated from 0.6.6 to 0.7.2.** Mobile editing now uses native focus behavior with a less intrusive unsaved-change state, while shared contracts and diagnostics remain compatible with the module UI.
- **Shared ntfy handling is standardized.** The WebUI Core now provides the common notification path used by the module instead of relying on release-specific UI plumbing.
- **Android Action launch reliability is improved.** The Core includes the PID-identity hang fix introduced in 0.7.1, reducing the chance of Action launches stalling on Android.
- **Visibility, cache and stale-response handling is hardened.** Core 0.7.2 refreshes the reliability baseline for visibility changes, duplicate actions and stale UI responses.
- **Upstream-informed WebUI reliability patterns were refreshed.** The Supercharger and AshLooper references were advanced and their relevant reliability concepts were independently adapted; no Supercharger tuning or GPL application code is imported.

## Supported families

| Family | Alpha10 Thermal materialization |
| --- | --- |
| Pixel 9 / 9a | Stock/no-overlay or sparse changed-file overlay |
| Pixel 10 / 10a | Stock/no-overlay or sparse changed-file overlay |
| Pixel 11 | Existing experimental sparse G6 path, unchanged |

## Compatibility and safety

- This release does not introduce a new performance preset or change the default Thermal profile.
- Pixel 11 classic PollingDelay and PassiveDelay controls remain unavailable.
- pTune Thermal coexistence override remains blocked on experimental Pixel 11 targets.
- ZRAM, Emerald Hill, LMKD and page-cluster controls remain separately controlled and reversible where supported.
- The WebUI remains loopback-only and uses the guarded typed control surface for standalone and embedded launch paths.

## Updating

Users already on the prerelease channel can update through the normal module update flow after the prerelease channel metadata is promoted. A reboot is required after flashing before judging runtime state.
