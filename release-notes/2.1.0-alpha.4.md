# Pixel Thermal & Memory Control 2.1.0-alpha.4

This is a **public vNext prerelease**. Stable users can stay on the stable channel; use this build if you intentionally want the newer vNext controls and WebUI.

## What changed since 2.1.0-alpha.3

- **Magisk Action now opens a standalone browser WebUI.** The interface shows the current module state and exposes the supported controls without relying on the old text menu for normal use.
- **Current settings are much easier to understand.** Active choices are shown directly, and Inventory switching uses cached verified data instead of repeatedly running the expensive validation path.
- **Runtime controls are available from the WebUI.** Polling, Thermal profiles, ZRAM, Emerald Hill, LMKD and ZRAM page-cluster actions use typed, guarded operations with preview support where applicable.
- **Fixed intermittent `server_not_ready` when opening the WebUI from Magisk Action.** The launcher now waits for the server process correctly before enforcing its final process identity.
- **Fixed an installer hang in the volume-key selection flow.** Installation now falls back safely if key-event reading times out instead of leaving the installer stuck.
- **Thermal validation is more reliable on non-English system locales.** Numeric processing is locale-stable, avoiding decimal-format problems during stock-derived validation.
- **Mobile WebUI usability is improved.** Action cards, tabs, status labels and Inventory views are clearer on narrow screens, and active/blocked actions are easier to distinguish.

## Compatibility and safety

- This remains the same single Android 17 vNext line for the supported Pixel 10 / 10a and Pixel 9 / 9a families introduced by the previous prerelease.
- Device/build validation remains fail-closed before Thermal changes are materialized.
- Experimental **LMKD 1%**, **Emerald Hill max lock** and **ZRAM page-cluster 0** remain opt-in and require explicit confirmation.
- Pixel 9-series and Pixel 10a keep their conservative experimental Thermal policy, including the current +1 °C Outdoor limit where applicable.
- Stable and prerelease update channels remain separate.

## Updating

Users already on the prerelease channel can update through the normal Magisk module update flow. A reboot is required after flashing so the new module runtime becomes active.
