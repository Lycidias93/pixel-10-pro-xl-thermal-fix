# Pixel Thermal & Memory Control 2.1.0-alpha.5

This is a **public vNext prerelease**. Stable users can stay on the stable channel; use this build if you intentionally want the newer vNext controls, broader Pixel support and WebUI features.

## New in 2.1.0-alpha.5

- **KsuWebUI can now open the module WebUI directly inside its embedded WebView.** The module starts the same local loopback WebUI used by the normal browser path, so status, settings and actions work without the previous `404 Not Found` / disconnected screen.
- **Magisk Action and KsuWebUI now work in parallel.** Magisk Action still opens the standalone WebUI in the default browser, while KsuWebUI can keep the interface inside its own WebView. Both use the same guarded localhost API rather than separate control backends.

## Included from 2.1.0-alpha.4

Alpha5 also includes all user-facing Alpha4 changes:

- **Magisk Action opens a standalone browser WebUI.** The interface shows the current module state and exposes supported controls without relying on the old text menu for normal use.
- **Current settings are much easier to understand.** Active choices are shown directly, and Inventory switching uses cached verified data instead of repeatedly running the expensive validation path.
- **Runtime controls are available from the WebUI.** Polling, Thermal profiles, ZRAM, Emerald Hill, LMKD and ZRAM page-cluster actions use typed, guarded operations with preview support where applicable.
- **The intermittent `server_not_ready` WebUI startup failure is fixed.** The launcher waits for the server process correctly before enforcing its final process identity.
- **The installer volume-key timeout hang is fixed.** Installation falls back safely if key-event reading times out instead of leaving the installer stuck.
- **Thermal validation is more reliable on non-English system locales.** Numeric processing is locale-stable, avoiding decimal-format problems during stock-derived validation.
- **Mobile WebUI usability is improved.** Action cards, tabs, status labels and Inventory views are clearer on narrow screens, and active/blocked actions are easier to distinguish.

## Compatibility and safety

- This remains the same single Android 17 vNext line for the supported Pixel 10 / 10a and Pixel 9 / 9a families.
- Device/build validation remains fail-closed before Thermal changes are materialized.
- Experimental **LMKD 1%**, **Emerald Hill max lock** and **ZRAM page-cluster 0** remain opt-in and require explicit confirmation.
- Pixel 9-series and Pixel 10a keep their conservative experimental Thermal policy, including the current +1 °C Outdoor limit where applicable.
- The WebUI remains loopback-only; KsuWebUI is used only to bootstrap the same local authenticated session and is not used as a second arbitrary root-command backend.
- Stable and prerelease update channels remain separate.

## Updating

Users already on the prerelease channel can update through the normal module update flow. A reboot is required after flashing so the new module runtime becomes active.
