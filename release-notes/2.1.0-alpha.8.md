# Pixel Thermal & Memory Control 2.1.0-alpha.8

This is the next **vNext hardware-test candidate** after Alpha7. Stable users can remain on 2.0.4, and Alpha7 remains the current public prerelease until this exact Alpha8 candidate passes the required device gate.

## New in 2.1.0-alpha.8

- **Pixel 11 Thermal overlays are sparse.** On Tensor G6, only Thermal JSON files whose validated candidate bytes actually differ from the cached stock source are materialized under the module overlay.
- **Untouched stock Thermal files stay outside the overlay.** Unmodified G6 graph members are preserved byte-for-byte, including their original trailing-newline state, so formatting alone cannot create a false sparse-overlay diff.
- **Full-stock behavior is preserved.** Stock polling + Stock Thermal + Stock recovery still produces no Thermal JSON overlay at all.
- **Pixel 11 policy is unchanged.** Classic PollingDelay and PassiveDelay remain Stock-only; Outdoor Safe remains capped at +1 °C on the master `VIRTUAL-SKIN` definition in `thermal_info_config_common.json`, while same-named peripheral graph entries stay stock.
- **Recovery remains independent.** HotHysteresis and MaxReleaseStep keep their separate controls, while only the modified common Thermal config is materialized.
- **Boot/runtime verification is sparse-aware.** Changed files are verified against generated module output; untouched files are verified against the cached stock source.

## Compatibility and safety

- Pixel 9/9a/10/10a keep the existing full three-file overlay contract; sparse materialization is Pixel 11 / Tensor G6 only.
- Pixel 11 classic PollingDelay and PassiveDelay controls are not exposed.
- pTune Thermal coexistence override remains blocked on experimental Pixel 11 targets.
- ZRAM, Emerald Hill and page-cluster experiments remain separately controlled and reversible where supported.
- The WebUI remains loopback-only and uses the same guarded typed control surface for standalone and embedded launch paths.

## Updating

Alpha8 is not promoted to the public prerelease channel until exact-head hardware acceptance is complete. The CI artifact is for the bounded device test cycle only; reboot after flashing before judging runtime state.
